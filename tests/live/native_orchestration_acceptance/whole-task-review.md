# Independent whole-task acceptance contract

`whole-task-acceptance.json` is evaluator-only. It freezes the current requested
scope and stage oracles; it is not an answer pack, solver context or run result.
All 400 explicitly tracked configuration/task cells start **unrun**. Historic
failed attempts remain in their original cohorts and cannot be overwritten.

The primary breadth denominator stays the original 100 tasks × two local Omni
models = 200 first-attempt cells. The user also requested all-device Ornith
validation, so the same full 100 cases are separately tracked for each Egg:
200 additional intended remote cells. Earlier messages did not numerically pin
remote repetitions; the JSON identifies this interpretation rather than claiming
that the existing local protocol specified 400 cells. Results on MD2/no-Kev Eggs
cannot establish local Kev/MD3.1 behavior.

Before breadth, use three unchanged existing cases:

| Case | Distinct family and user journey | Required local cells |
| --- | --- | --- |
| LHN-047 | Editorial: ten exact edits, protected text, change index, two official style sources, ZIP and reopened outputs | Ornith and Qwen |
| LHN-001 | Migration dossier: compare versioned official API documentation, resolve four examples, author explanations/matrix, archive and reopen | Ornith and Qwen |
| LHN-053 | Unit-aware data story: fifteen rows, thirteen valid readings, preserved raw data, Calc formulas, two-series chart, note/PDF and reopened agreement | Ornith and Qwen |

None of these cases requires an unimplemented media/event injector. Actual
ordinary-app ownership and native accessibility, source freezes and exact loaded
weights remain prerequisites. Selecting these tasks does not certify readiness.
Use the original frozen goals and file specifications. The only permitted goal
substitution remains `WORKBENCH` to the fresh owned absolute path. Give no oracle,
UI procedure, expected action or precomputed output to the solver.

Require each model's first attempt and then three independently reset attempts
in total for each selected initial case/configuration. Additional runs form a
separate reliability cohort; no best-of-three substitution for a failed first
attempt. For local models this is six primary initial cells plus twelve
additional runs. Remote initial coverage and repetitions have the same separate
accounting. Full breadth repetition, if subsequently run, gets a new named cohort.

The JSON enumerates every original criterion and independent evidence/falsification
condition for all three selected cases, with particular detail for all ten
LHN-047 criteria. Exact saved bytes and ZIP membership are necessary but cannot
establish website navigation, native reopening, actual physical Save/delivery
mouse use or session memory. A successful compiler or controller test does not
close any whole-task cell.

Method review must distinguish authored content from executed code. LHN-001
explicitly requests practical Python examples in the research document; LHN-053
explicitly requests Calc formulas. Both are permitted content in their intended
applications. The forbidden paths are actual solver shell/terminal/devtools,
macro, direct filesystem/fetch or operator completion. Use execution context and
typed intent, not code words or suffixes, to decide.

## Concrete gaps discovered in the SOP/runtime audit

1. **Timers are different clocks.** The runner allows 1,800 seconds and drains
   for 300 seconds. The deployed portal passes `min(runtime.timeout_s,1800)` to
   the controller; `PortalConfig` defaults to 1,200 and reads
   `OMNI_PORTAL_TIMEOUT_S`. Prove the loaded configuration before claiming a
   1,800-second controller condition. The unused function default alone does not
   establish the live limit. Any changed budget is a new declared cohort.
2. **The proposed 500-input ceiling is unenforced.** The frozen protocol and
   runner explicitly say so. Forty phases are bounded; the number of inner inputs
   is a separate measure. Implement and prove the input ceiling before reporting
   it as an enforced resource guard. Keep the existing no-progress stop.
3. **The deployment trap is a partial rollback.** It restores environment,
   system/user units and prior services. The updater fast-forwards the checkout
   first; neither this trap nor a restored unit proves restoration of previous
   Python/native/venv code. Retain the exact known-good generation and a supported
   restoration procedure, then verify actual source/model/residency/idle adoption.
4. **Method signals are incomplete.** `method_evidence` checks some guarded
   typing, physical pointer input and movement. It does not prove the pointer
   specifically used the required Save/delivery control and leaves GUI macro/code
   review pending. Require independent target/context and complete trace review.
5. **Source/worker summaries do not prove adoption.** The current runner's
   `source_state()` hashes a finite list of checkout files and its worker snapshot
   reads the standard daemon state. These cannot alone establish new effect,
   handoff or keymap imports in an isolated frontend. Preserve root's actual
   loaded-import/source and exact worker/device evidence separately.
6. **Fixture/oracle gaps are explicit.** Six screening cases LHN-083–088 need
   media materialization. Calendar cases LHN-077–082 and interruption cases
   LHN-089–090 need the original trigger-bound injectors. Across the suite,
   87/960 criteria have declared automatic implementations; 873 still require
   independent review or additional evaluators. The JSON lists each missing
   materializer case and family-level oracle counts. Missing automatic code does
   not prohibit diagnostic execution, but unreviewed criteria cannot pass.
7. **Layer coverage needs actual eligible use.** A unique native action may
   correctly skip Kev, and native text can correctly avoid visual inference.
   Record real eligible Kev and Moondream calls across the stage; do not force
   irrelevant calls or count configured endpoints as exercised coverage.
8. **Causal ablations stay separate.** Combined handoff and hierarchy changes may
   improve the task but do not establish which mechanism caused improvement.
   Keep one-factor captured-state comparisons as stated by the root SOP.

These are acceptance findings, not new automatic deployment permissions or a
reason to hide failed cells. Root owns integration, supported lifecycle and
serial real desktop/model testing. This verifier made no model/desktop/GPU calls.

At each handoff, supply the exact candidate/source/bundle identities plus raw
read-only artifacts. The verifier returns one verdict per mandatory criterion,
with evidence references and falsification if failed. Missing or ambiguous
evidence is inconclusive, never a pass. The active full goal remains incomplete
until the actual required cells and capabilities are independently verified.

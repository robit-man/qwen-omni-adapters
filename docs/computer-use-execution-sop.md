## 3. Evidence and stage states

Work items, attempts, source revisions and artifacts have distinct identities.
Never overwrite a failed attempt with a passing attempt. Each attempt records:

1. Immutable work-item code, specification revision, attempt UUID and parent.
2. Exact source revision and candidate file digests; loaded-runtime adoption
   evidence, not checkout identity alone.
3. Frozen goal and task signature; model, sampler, context/output budget, policy
   threshold, visual-model pin, host capabilities and expected device scope.
4. Initial UI ownership, input hashes, worker identities and healthy/idle state.
5. Exact structured model requests/responses, observed native states, input and
   effect receipts, relevant screenshots and independent artifact readbacks.
6. Verdict for every acceptance condition: pass, fail, inconclusive, or unrun.
7. Cleanup, unrelated-state preservation and downstream natural-idle evidence.
8. A durable manifest with byte lengths, SHA-256 hashes and readback verification.

Stages use `pending -> in_progress -> candidate -> verified -> integrated`.
An actual failing check uses `failed`; missing prerequisites use `blocked` with
the exact cause and prerequisite. `verified` applies only to the named acceptance
scope. A provider pass cannot promote a whole-task stage. `integrated` additionally
requires the tested source to be adopted and its integration gate to pass.
Semantic oracles requiring independent review remain inconclusive until reviewed.

The active goal remains active while any required outcome is missing. A status
update or unexecuted plan is not implementation progress. A wait must identify a
currently live process/session; poll it rather than restarting after an expired
observation window.

## 5. Architecture contract to implement

Every generated immediate action must preserve five distinct objects:

| Object | Owner and authority | Required contents |
| --- | --- | --- |
| User goal | Immutable task authority | Original request, constraints and frozen task signature |
| Plan/dependencies | Omni proposal | Current subgoal, prerequisites, unmet criteria and intended resource |
| Immediate transition | Source-bound planner claim | Current target identity/generation/scope, next operation, intended UI transition and originating phase |
| Input offer | Native controller | Fresh legal operation, exact device/window authority and one-use/idempotency binding |
| Effect/result | Fresh executor observation | Supported postcondition, observed transition, uncertainty and independent task relevance |

Prose predictions never become arbitrary literal UI-text oracles. Focus, exact
value writes, check states, selections and active-window contracts compile to
host-supported predicates. A literal value must retain its source binding.
Opaque activation/keyboard/scroll inputs may return a single-input observation
boundary when no stronger effect is supported; this grants no effect or task
credit. Add explicitly typed focus/popup/document transitions where fresh evidence
can establish them. A document change does not alone prove the requested resource
was acquired or that its content supports the answer.

The same immediate-operation explanation survives Omni, Kev, policy deferral,
pointer recovery and execution. Preserve it as a planner claim with original
source phase/goal/target binding; never relabel it as observed evidence. Recovery
must validate the current offer and target again. Native frame, geometry, focus,
namespace, lease and freshness checks remain authoritative.

Retain bounded observed parent/row/popup/label relationships rather than asking
the model to reconstruct them from concatenated names. Expand exact evidence
when needed. Missing or clipped information remains unknown. No task-specific
lexical routing, inferred labels or invented geometry-based hierarchy is allowed.

Recovery tracks target + operation + relevant state + failure cause outside the
renewable prompt. Rephrasing an assessment cannot make an unchanged failed
strategy novel. A genuinely changed relevant state can permit a new attempt;
uncertain input is never replayed blindly. Keep the no-progress limits and obtain
additional evidence or choose a different supported strategy.

The candidate is not released while any routing boundary drops typed transition
metadata. In particular, compact decisions, `ui_subgoal` and pointer recovery
must all preserve the descriptor into host comparison. A generic popup, focus or
document change is informational unless actual observed target/generation
linkage supports the intended immediate transition. An unrelated popup must not
clear an uncertain click. Missing linkage remains unknown.

Preserve useful action chaining by compiling a bounded verified prefix: each
focus, exact write, check, selection or switch gets fresh guards and its own host
readback. Stop at the first opaque input, failed check or uncertainty and return

claim. Do not assume that reducing every plan to one operation fits the unchanged
